Migrated from Atmosphere `clinical:data-exporter` (2026-06-13, UNLICENSED; nested repo, remote symptomatic/data-exporter). Data / medical-records exporter — collection export, FHIR bundle export, de-identification. Route `/export-data` → ExportPageNew. Migrated **to fix the admin-tools decommission regression**: the Atmosphere data-exporter had a hard `api.use('clinical:admin-tools')` that broke package selection once admin-tools moved to deprecated/.

- **admin-tools repoint (the point):** `lib/MedicalRecordsExporter.js` imports admin-tools' `Anonymizer` + `PATIENT_COMPARTMENT_MAP`/`buildPatientQuery` (used for compartment-collection de-identification). Repointed `meteor/clinical:admin-tools/lib/{Anonymizer,PatientCompartmentMapper}` → `@node-on-fhir/admin-tools/lib/…` (npm subpath exports; admin-tools' lib files are self-contained — lodash + meteor/random). `@node-on-fhir/admin-tools` is a peer. MedicalRecordsExporter is reachable on the client (CollectionManagement + FileSystemContent import it).
- **Bare-global fix:** `MedicalRecordsExporter = {…}` (strict file) → `const MedicalRecordsExporter = globalThis.MedicalRecordsExporter = {…}`.
- **Legacy old-MUI UI dropped:** `ExportComponent.jsx` (+ `ExportPageLegacy`, `ExportPage`) import `@material-ui/*` (v4) + `material-ui/svg-icons` (v0.x), unreachable now — client.js routes/exports only the modern `ExportPageNew` + `CollectionManagement`. Legacy files kept for reference but unbundled.
- **Server:** server/index.js loads the sole addFiles server file `methods.proxy.js` (HTTP export proxy; self-contained). Dropped the `clinical:admin-tools` + `clinical:hl7-resource-datatypes` api.use lines (the latter had 0 source imports).
- **Deps:** papaparse/xml2js/xlsx are app-level → declared as peers (no fresh install / no lockfile churn). `certs/`, `tests/`, `.circleci/` skipped. `fire`→`Whatshot`. Not in `.meteor/packages` (was loaded via `--extra-packages`; now load via `EXTRA_WORKFLOWS=@node-on-fhir/data-exporter`). Nested repo → history preserved on `npm-migration`.
